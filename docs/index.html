What it can catch

How big a drop does the gate need to see?

A real drop is only caught if it clears both the threshold and the noise. More tasks and steadier tasks make smaller drops visible. The dashed curve is the original plan: 300 tasks and more noise per task.

The rule

How a pull request gets judged

  1. Run both promptsThe last good prompt and the PR's prompt answer the same 149 gate tasks, three times each.
  2. Score every answerExact checks for numbers, citations and abstention. A certified LLM judge grades free-text answers.
  3. Bootstrap the differenceAverage the repeats per task, then resample tasks 10,000 times on the paired differences.
  4. DecideBlock if the drop is at least 2 pts and the upper bound is below zero. Warn if only the estimate crosses. Otherwise pass.
  5. ReportOne comment on the PR, a status check that can block the merge, and the traces as an artifact.

What this does not show. All 100 real agent answers were correct, so the 40 failures are constructed: a changed number, a dropped fact, an unsupported claim, a wrong citation. They are fairly obvious. Kappa shows the judge rejects constructed errors and accepts correct answers. It does not show how the judge handles subtle real mistakes.

The two disagreements are short answers that left out a detail present in the reference ("one-time", "March and September"). The judge's stricter reading follows the rubric. The labels were not changed to match it.

Limits

What to keep in mind

  • The gate set has 149 tasks, not the 300 in the original plan, to fit a small model budget. That is why only drops of roughly 6 points or more are reliably caught.
  • The corpus has 40 synthetic documents and five conflicting pairs, so the conflicting-documents category tests about five distinct facts. Splits overlap in facts, not in wording; 26 gate questions were reworded after a near-duplicate check.
  • Datasets were spot-checked on a 10% sample. Label-noise floor: dev 9.1% (95% interval 1.6 to 37.7), gate 0.0% (0 to 18.4).
  • The planted regression took three tries to become real. The first version changed nothing measurable, which is itself a reason to measure a gate against a known-bad change.
